i What this is & the golden rule for UAT

This is your User Acceptance Test environment: a private, local-only copy you drive by hand to confirm every feature behaves. Nothing here is exposed to the internet.

Keep it private. Start the server with the default address only (127.0.0.1 / localhost). Do not add --host 0.0.0.0 or put it behind a public tunnel during UAT — that would make it reachable from outside.
UAT uses bundled sample data only — no MEED/ProTenders credentials, no live portals, no real emails. Alerts default to the console channel, so they print to the terminal instead of going anywhere.

1 One-time setup

Open a terminal in the project folder and create an isolated Python environment.

# from the repo root
cd gcc-door-intel
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
Dependencies installed with no errors. Expected: pip finishes; last line is a success/“Successfully installed …”.

You do not need a .env file for UAT. It's only for real email/webhook alerts later. Console alerts work with zero config.

2 Load the sample data (seed)

This runs the entire pipeline once — import → stage → normalize → de-duplicate → enrich → score → alert.

python -m scripts.seed

What to look for in the output

Bottom line says 11 unique projects in the database. 12 sample rows are ingested but one is a cross-source duplicate, so you get 11.
Lusail Marina Twin Towers shows sources [meed,protenders]. Proves de-duplication: the same project from two platforms merged into one record.
The two C rows (Sohar … Compound = cancelled, Salalah … Warehouse = on-hold) have score 0.0. Proves auto-disqualification of dead projects.
A console [ALERT] block printed listing new Tier-A projects. Proves the alert layer fires on ingestion (console channel).

3 Start the dashboard

uvicorn app.main:app --reload --port 8000

Then open http://localhost:8000 in your browser.

The Pipeline board loads with project cards in columns. Expected: a dark top bar reading “SBK · GCC Door Intelligence INTERNAL”.
To stop the server later: press Ctrl + C in the terminal.

4 Test: Pipeline board & KPIs (/)

KPI strip shows Projects = 11 and a Tier A count. Also shows pipeline value, win rate (— until you mark wins), pre/post-tender split.
Cards are colour-coded by tier (green=A, amber=B, grey=C) and show score + estimated doors. Fire-rated projects show a 🔥 mark.
Use the filters: pick Country = Saudi Arabia, click Filter — only Saudi projects remain. Try Tier = A and a Min score too; the board should narrow accordingly.

5 Test: Project detail & “why this score” (/project/…)

Click the Lusail Marina Twin Towers card.

A score breakdown table shows each factor (funding_status, spec_influence, door_relevance, fire_rating, reachability, country) with normalized value and points. This is the “why” behind the tier — points should sum to the total score.
Source references lists both meed and protenders entries. Confirms the merged record kept full traceability to both platforms.
Change Pipeline status to pursuing, set Assigned to = your name, add a note, click Save. You return to the detail page; go back to the board and the card has moved to the “pursuing” column.
On a project, change Project status (e.g. to awarded) and Save — the score re-calculates. Proves scoring is live: changing stage updates score/tier immediately.

7 Test: Import an export file (/upload)

Click Import file. Choose profile meed and upload data/samples/sample_meed.csv again.

Upload succeeds and redirects to the board; project count does not jump by 5. Re-importing the same rows re-matches existing projects instead of duplicating them — that's the dedupe doing its job.
To test a brand-new source, copy config/mappings/generic.yaml, point its left-side keys at your file's column headers, and pick it on the upload page.

8 Test: Map view (/map)

Click Map — a GCC map shows coloured dots (green/amber/grey by tier). Clicking a dot shows the project name (a link), country, type, tier and score.
The map tiles load from OpenStreetMap, so this one step needs internet. Everything else works fully offline.

9 Test: JSON API (/api)

Open these in the browser (or curl them):

/api/projects?tier=A returns JSON of Tier-A projects with their sources.
/api/kpis returns the KPI numbers.
/api/docs shows the interactive API documentation.

10 Test: Alerts & digest

Alerts fire automatically on ingestion (you saw them in step 2). To trigger a digest on demand, run this in a second terminal (with the venv active):

python -m scripts.run_ingest --digest
A [ALERT] GCC Door Intel — daily digest block prints, listing Tier A + B projects. Console is the UAT channel. Email/webhook are switched on later via config.yaml + .env.

11 Optional: tune the scorecard & re-test

Everything that drives scoring lives in config/config.yaml — no code changes needed. Try raising the Tier A threshold to see fewer A's:

# config/config.yaml
scoring:
  tiers:
    A: 85   # was 70
    B: 45
Re-seed (python -m scripts.seed) and refresh — fewer projects are Tier A now. Confirms all thresholds/weights are config-driven, not hardcoded.

✓ Reset between test runs

The seed script wipes and rebuilds the database each time, so to get back to a clean slate just run:

python -m scripts.seed

To start completely fresh you can also delete data/gcc_door_intel.db.
